# 拡張機能の利用状況と改善判断

GA4 プロパティは `463560127`（investee-extension）。Web 版とは別の利用者として計測する。

| 確認すること             | 指標・分析軸                                      | 改善の入口                                             |
| ------------------------ | ------------------------------------------------- | ------------------------------------------------------ |
| 使われているか           | popup_open の総ユーザー数とイベント数             | 対応サイトの導線・利用案内                             |
| 表示できているか         | report_result の表示結果、サイト名                | empty なら収録データ、error なら API・対応サイトの検出 |
| 分析に使われているか     | analysis_interaction の総ユーザー数、グラフの種類 | グラフの説明・ナビゲーション                           |
| Web へ調査を続けているか | outbound_click、link_domain                       | 比較機能への導線                                       |
| 更新で悪化していないか   | 拡張機能バージョン別の表示結果と操作数            | 新旧バージョンで再現確認                               |

過去 28 日と前の 28 日で件数と率を一緒に確認する。利用者が少ない時の率だけで結論を出さない。
データが少ない間はイベント数の単純な割算をファネル転換率と呼ばない。同じセッションの経路を調べる場合は GA4 のファネル探索で順序とセッションを指定する。

## 発火条件とデータ

- `popup_open`: ポップアップを開いた時に一度だけ。
- `report_result`: 実際の表示に使う Redux ストアが success / empty / error になった時。読込中や再レンダーでは送らない。
- `analysis_interaction`: 手動のグラフ切替、自動切替設定の変更。自動再生そのものは送らない。キーイベントに設定する。
- `outbound_click`: 株探・Web 版へのリンクを操作した時。Web 版へのリンクは `utm_source=investee_extension` で識別する。

カスタム定義（イベントスコープ）: サイト名=`site_domain_name`、表示結果=`result_status`、分析操作=`interaction_type`、グラフの種類=`chart_type`、拡張機能バージョン=`extension_version`。
`unavailable_count` は 3 表のうち一つ以上が表示不可のレポート数。通信失敗とは別。

ブラウザ内のランダムな ID を継続使用し、30 分の無操作でセッションを切り替える。ポップアップの再レンダーや操作ごとには変えない。
送信するのは対応サイトのドメイン・結果・操作・バージョン。銘柄、企業名、自由入力、閲覧 URL、他タブの履歴は送信しない。
画面下部の「改善のため利用状況を送信する」で以後の計測を停止できる。開発ビルドは常に計測しない。

## 実装・運用

`src/popup/analytics.ts` が `https://investee.info/api/analytics/extension` へ送信し、Rails が GA4 Measurement Protocol へ中継する。秘密キー・測定 ID はサーバだけが管理し、`VITE_GOOGLE_*` は不要。host_permissions の追加も不要。
本番ビルドは `ANALYTICS_ENABLED` と package.json 由来のバージョンだけを埋め込む。計測失敗で画面を止めず、再試行で件数を膨らませない。

サーバ設定・イベント契約・反映時差は [Web リポジトリの運用文書](https://github.com/shin4488/financial-statement/blob/main/docs/analytics/README.md) を参照。
MP のみの計測なので、地域・端末・流入・新規/再訪を Web SDK と同等には評価しない。拡張ではサイト別の総ユーザー数と操作・結果を中心に見る。

公開前に計測中継 API を先行デプロイし、GA4 のリアルタイムでも受信を確認する。HTTP 204 だけでは GA4 に反映された証明にはならない。通常レポートへの反映には 24 ～ 48 時間かかる場合があり、新しい計測は過去に遡らない。
